_____
Keeper es una máquina fácil enfocada en un servicio web que ejecuta `Request Tracker` y un administrador que usa el gestor de contraseñas `keePass`. El punto de entrada son las credenciales por defecto que usa `Request Tracker`, enumerando los usuarios del sistemas tickets encontramos la contraseña de un usuario que nos permite conectarnos al servidor por `SSH`. Una vez dentro enumerando el host encontramos un archivo ZIP con una base de datos `keePass` y un volcado de memoria del proceso. Aprovechando el `CVE-2023-32784` conseguimos extraer la master password desde el volcado de memoria y accedemos a la base de datos, donde encontramos una clave privada `SSH` en formato `PuTTY (PPK)` perteneciente a `root`.

# Enumeración web

Al acceder a `http://10.129.18.185` en el navegador, la página no muestro contenido propio sino un enlace que nos redirige a `tickets.keeper.htb/rt/`.  

![img](assets/kep/kep1.png)

Añadimos este dominio a nuestro `/etc/hosts`, a partir de ahora cualquier petición a `tickets.keeper.htb` se resolverá contra la `IP` de la máquina. 

```bash
❯ echo "10.129.18.185  keeper.htb tickets.keeper.htb" | sudo tee -a /etc/hosts
```
## Panel de autenticación - Request Tracker

Al acceder al dominio `http://tickets.keeper.htb/rt/` encuentro una panel de login perteneciente a `Request Tracker (RT)`, una aplicación de gestión de tickets de soporte desarrollada por `Best Practical Solutions`. Tenemos la versión exacta visible tanto en el encabezado del formulario como en el pie de página `RT 4.4.4`

![img](assets/kep/kep2.png)

Con una simple búsqueda en Google vemos que la aplicación dispone de credenciales por defecto tras su instalación, las prueba directamente y accedo con éxito a la aplicación. 

![img](assets/kep/kep3.png)

# Shell as root

Nada mas entrar enumeramos el directorio de nuestro usuario consiguiendo la primera flag `user.txt` y descargó a mi máquina el archivo `RT30000.zip` para analizarlo. 

![img](assets/kep/kep5.png)

```bash
scp lnorgaard@10.129.18.185:/home/lnorgaard/RT30000.zip .
```

El binario tiene dos ficheros en su interior:
- `passcode.kdbx`: es una base de datos de `KeePass`, un gestor de contraseñas que almacena todas sus credenciales cifradas bajo una única `master password`.
- `keePassDumpFull.dmp`: un volcado completo de la memoria del proceso `keePass` en el momento en que estaba en ejecución. 

```bash
❯ 7z l RT30000.zip

...[snip]...

--

Type = zip
Physical Size = 87391651

   Date      Time    Attr         Size   Compressed  Name
------------------- ----- ------------ ------------  ------------------------
2023-05-24 12:51:31 .....    253395188     87387677  KeePassDumpFull.dmp
2023-05-24 12:51:11 .....         3630         3630  passcodes.kdbx
------------------- ----- ------------ ------------  ------------------------
2023-05-24 12:51:31          253398818     87391307  2 files
```

Descomprimimos el `RT30000.zip`, investigamos que tipo de fichero es exactamente el `.dmp`. 

```bash
❯ file KeePassDumpFull.dmp
KeePassDumpFull.dmp: Mini DuMP crash report, 16 streams, Fri May 19 13:46:21 2023, 0x1806 type
```

El comando `file` nos identifica el fichero como un `Mini Dump`, es decir un volcado de memoria del proceso `KeePass`. Una búsqueda en Google con la salida que nos da el comando `file` nos muestra directamente el `CVE-2023-32784`, una vulnerabilidad de `KeePass 2.X` que permite recuperar la master password casi en texto claro desde un volcado de memoria del proceso.  

![img](assets/kep/kep6.png)
## Explotando CVE-2023-32784

Nos descargamos el PoC en python de este repositorio [z-jxy](https://github.com/z-jxy/keepass_dump?tab=readme-ov-file) y lo ejecutamos contra el `.dmp`. 

```bash
❯ python3 keepass_dump.py -f KeePassDumpFull.dmp --recover
[*] Searching for masterkey characters
[-] Couldn't find jump points in file. Scanning with slower method.
[*] 0:	{UNKNOWN}
[*] 2:	d
[*] 3:	g
[*] 4:	r
[*] 6:	d
[*] 7:	
[*] 8:	m
[*] 9:	e
[*] 10:	d
[*] 11:	
[*] 12:	f
[*] 13:	l
[*] 15:	d
[*] 16:	e
[*] Extracted: {UNKNOWN}dgrd med flde
[?] Recovering...
[-] Couldn't verify plaintext match in dump for: dgrd med flde
```

La herramienta extrae la mayor parte de la contraseña pero deja cuatro huecos en las posiciones 0, 1, 5 y 14. El flag `--recover` tampoco ayuda, la contraseña en texto plano no está almacenada en el `.dmp`. Los huecos son probablemente caracteres no-ASCII que `KeePass` no puede representar correctamente en memoria. Si metemos el resultado que tenemos en Google la búsqueda nos muestra el nombre de un postre tradicional danés. Esto no es casualidad ya que si hemos estado atentos en el perfil del usuario `lnorgaard` en `Request Tracker` el idioma que tenía configurado era el Danés. 

![img](assets/kep/kep7.png)

Abrimos el fichero `passcodes.kdbx` con `keepassxc`

```bash
keepassxc passcodes.kdbx &
```

Introducimos `rødgrød med fløde` y tenemos acceso a la base de datos

![img](assets/kep/kep.png)

Enumerando la base de datos encontramos una carpeta `Network` con dos entradas, una de ellas para el usuario `root`. 

![img](assets/kep/kep8.png)

La entrada `root` contiene dos cosas relevantes, una contraseña que pruebo directamente contras `SSH` sin éxito y una clave SSH en formato `PuTTY (.ppk)` almacenada en el campo notas con cabecera `PuTTY-User-Key-File-3: ssh-rsa`. El formato `PPK` es el formato propietario de `PuTTY`, un cliente SSH de Windows. Para usarlo en Linux necesitamos convertirlo al formato `OpenSSH` estándar. De nuevo realizando una búsqueda estándar en Google nos muestra como transformar la clave `.ppk` a nuestro formato `OpenSSH` para intentar conectarnos como `root`


![img](assets/kep/kep9.png)

Una vez realizados los pasos nos conectamos a la máquina consiguiendo acceso como `root`

```bash
ssh -i id_rsa root@10.129.18.185
```
